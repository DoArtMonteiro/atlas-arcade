# Atlas Arcade

Geography mini-games and a boss stage, in a retro arcade cabinet.

**Demo:** https://atlasarcade.app

**Status:** Deployed prototype. The daily percentile is simulated; leaderboard scores and balances do not have server-side integrity protection.

## Current data trust boundary

As of 29/10/2026, the public `master` client writes balances and scores directly to Supabase. Draft [PR #1](https://github.com/WhiteBlindness/atlas-arcade/pull/1) proposes server-side protection, but it is not merged or deployed. The published leaderboard and balances therefore lack a server-validated trust boundary.

## Results integrity

The daily results screen and share text display a "You beat X% of players today" figure generated by a logistic curve. It is not calculated from player results and is not a real ranking. See the [percentile function](src/lib/daily.ts) and [share text](src/lib/share.ts).

The 11 mini-games are GeoRadar, Capital Strike, Flag Frenzy, Peaks & Valleys, Tectonic Snap, Frontier Face-Off, One Strike, Urban Legends, Skyline Silhouette, Border Blitz, and Stat Attack. **Atlas Jackpot** is a separate 15-stage boss run. Entry requires sign-in and five tokens; stages 5, 10, and 15 are reward milestones within the run.

## Motivation

Online geography quizzes often take one of two routes. Educational games can feel like school, while polished casual games can use approximate scoring or outdated facts. Wordle showed that a daily puzzle can be quick, shared, and worth returning to because it is limited.

Atlas Arcade combines a daily puzzle, an arcade-style game loop, and a quiz engine based on real geography data. Its games cover location, names, elevation, skylines, and borders.

## The idea

The CRT skin is the surface. Underneath is a quiz engine built on country and city data, with distance-based scoring. The retro styling sits on top of the geography content and does not replace it.

The 11 mini-games offer two modes. **Daily Challenge** is the same puzzle worldwide, seeded by UTC date, with streaks and account leaderboard rankings. **Arcade** supports repeatable play while coins remain; each run spends one coin, which regenerates over time. The daily challenge stays limited, while extended play remains optional. Atlas Jackpot is a separate boss run, not a Daily Challenge.

## Problems worth solving

**One shell for every game.** A change to the mode selector should not require edits in each game. The game-select grid, Daily/Arcade modal, HUD frame, scoring reveal, and coin spend each live in one shared shell. A game supplies its round logic and accent colour through `gameTheme.ts`.

**The comparison moment cannot lag.** Comparison images are preloaded during the guess phase, so the reveal path does not fetch them on demand. This keeps scoring feedback focused on the result rather than a network request.

**Dark theme without a flash.** The arcade is dark by default and saves the user's choice, so the theme must be applied to `<html>` before first paint. Otherwise, each load starts with a white flash. A synchronous inline script runs before hydration. `layout.tsx` documents the React setup and two warnings in this Next.js fork that isolation testing found cannot be fixed in application code.

**An energy economy that respects the player.** Arcade play is gated by coins, and the balance is easy to get wrong in the greedy direction. The rules (`src/lib/tokens.ts`): hold at most 5, regenerate 1 every 2 hours while below the ceiling, at most 10 granted per UTC day, reset at UTC midnight alongside the daily challenge. Guests use a localStorage balance; signed-in players use Supabase. Premium tokens and Atlas Jackpot access require an account.

**High-energy visuals with limits.** Retro visuals can include flicker, glitch, and neon. The documented design intent is to avoid strobing and to avoid conveying information through colour or motion alone. The repository does not include a photosensitivity assessment.

## Design intent and implementation

These documented rules guide the implementation; they are not all covered by automated checks.

- **Square corners by default.** Cards, buttons, modals, and inputs use square corners; a small number of coin and game indicators use rounded shapes.
- **Accent glow is the default elevation treatment.** The GeoRadar country-picker dropdown is an implementation exception and uses a black drop shadow ([source](src/components/games/globle/GuessInput.tsx)).
- **One neon accent per game**, defined once in `src/lib/gameTheme.ts` and carried through the game's card, its mode-select modal and its in-game HUD. Yellow belongs to Atlas Jackpot alone.
- **Modals require an explicit close action.** Use the `X` or `[ CLOSE ]` control. A backdrop click never closes a modal. Spending a coin or locking an answer should require intent.
- **Motion and contrast have documented limits.** Motion is designed to avoid strobing. The light-theme contrast check covers game accent tokens against the two backgrounds listed in `DESIGN.md`; it is not a full application WCAG AA audit. The repository does not include a photosensitivity assessment.

Full visual system in `DESIGN.md`, product intent in `PRODUCT.md`.

## Stack

Next.js App Router · TypeScript · Zustand for game state · Supabase for auth, profiles, leaderboards and referrals · react-globe.gl / Three.js for globe visuals · Tailwind · Press Start 2P + VT323

Deployed on Vercel. The interface is localised through `src/lib/i18n.ts`.

## Running it

```bash
npm install
npm run dev
```

A Supabase project is optional. To enable sign-in, leaderboards, and referral bonuses, set `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` in `.env.local`, then apply the files in `supabase/migrations/` in filename order. Anonymous play works without Supabase.

Country data is regenerated with `node scripts/fetchCountries.mjs`.
